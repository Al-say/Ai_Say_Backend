# 业务说明文档（独立维护）

更新时间：`2026-04-13`

## 1. 原因（为何与接口契约分离）

- 接口契约文档是“代码事实文档”，目标是可核对、可回归、可自动化比对。
- 业务说明涉及“原因、取舍、策略、排障路径”，会随阶段目标和问题演进频繁变化。
- 将两者拆分可以避免：
  - 业务叙述污染接口事实；
  - 接口事实被历史背景和策略描述覆盖；
  - 联调时“事实口径”和“解释口径”混用。

结论：
- 接口事实只看 `docs/接口契约文档.md`
- 原因/策略/排障只看 `docs/业务说明文档.md`

## 2. 策略（如何维护）

### 2.1 文档职责
- `docs/接口契约文档.md`：
  - 只写路径、方法、鉴权、请求、响应、类型字段。
  - 不写“为什么这么设计”。
- `docs/业务说明文档.md`（本文）：
  - 只写原因、策略、排障、已知限制、后续治理计划。
  - 不写接口字段级契约明细。

### 2.2 更新触发条件
- 触发更新“接口契约”：
  - Controller 路径/方法变更
  - 鉴权规则变更
  - 请求/响应结构变更
- 触发更新“业务说明”：
  - 出现线上/联调问题，需要补根因与排障策略
  - 架构或策略调整（如鉴权收口、兼容策略、配置治理）
  - 风险评估或治理优先级变更

### 2.3 最小维护流程
1. 先改代码并验证。
2. 更新接口契约中的代码事实。
3. 更新业务说明中的原因/策略/排障。
4. 在 PR 描述中分别引用两份文档。

## 3. 排障（标准流程）

### 3.1 先判定问题类型
- A 类：鉴权与身份链路（401/403、`@CurrentUser` 失败）
- B 类：接口行为与契约不一致（字段缺失、状态码错误）
- C 类：数据归属与历史查询（owner 不一致、越权或查不到）
- D 类：配置生效漂移（同功能多套配置键、环境行为不一致）
- E 类：业务链异常（如特定接口 500）

### 3.2 通用排障步骤
1. 复现：固定请求、身份、参数、环境。
2. 定位：按“入口控制器 -> 服务 -> 仓储/外部依赖”逐层定位。
3. 校验契约：对照 `docs/接口契约文档.md` 检查实际行为是否偏离。
4. 修复：优先收口一致性（身份、owner、配置入口），再修表现层。
5. 回归：
  - 编译通过；
  - 关键路径接口验证通过；
  - 必要的定向测试通过。
6. 沉淀：把原因、策略、排障证据回填本文档。

### 3.3 当前项目建议的优先级规则
- 先基线：可编译、可认证、身份可信。
- 再一致性：owner 归属、配置入口、权限边界。
- 后优化：功能扩展、体验优化、广覆盖测试。

## 4. 已知实践约束（当前仓库）

- 接口契约以代码为准，不以历史文档为准。
- 安全判定需同时看：
  - `SecurityConfig` 的路由规则；
  - Handler 是否要求 `@CurrentUser`。
- 历史兼容逻辑属于过渡策略，应定期评估是否迁移并收敛。

## 5. 文档协作约定

- 新增接口或变更接口：必须同步更新接口契约文档。
- 变更业务策略或排障结论：必须同步更新本文档。
- 禁止在接口契约文档中写“推断”“建议”“背景解释”。
- 禁止在业务说明文档中复制粘贴字段级契约表。
